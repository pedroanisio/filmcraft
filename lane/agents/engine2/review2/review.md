- **P1 — Scene import can exhaust memory through intermediate undo snapshots** — [interchange.rs:84](/home/admin/src/filmcraft-wt/engine2/crates/engine/src/interchange.rs:84). A valid scene containing 10,000 distinct image asset IDs referencing one tiny PNG passes the input limits. `merge_and_link` performs one `s.edit` per asset, while `edit_group` disables the history limit and retains every full project snapshot until completion. This produces quadratic memory consumption and can terminate the process through allocation failure. **Fix:** merge and apply all media-link updates in one edit, retaining only the pre-import snapshot.

- **P2 — Rendered imports bypass the filesystem-backed check** — [interchange.rs:220](/home/admin/src/filmcraft-wt/engine2/crates/engine/src/interchange.rs:220). With native virtual-file services and an installed renderer, `file.importScene {mode:"rendered"}` delegates through `import_streamed` to `import_bytes`, which calls `open_scene_bytes` without checking `is_filesystem_backed`. Preview consequently passes a virtual path to the external process, causing failure—or rendering an unrelated disk file at that path. Export and cache reopening instead select the placeholder, so behavior also changes across those paths. **Fix:** apply the filesystem check in `import_bytes` and use `virtual_placeholder` with its warning when false.
